# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Команды

```bash
npm start          # запуск (node app.js), http://localhost:3000
npm run lint       # ESLint + проверка шаблонов (pug + pug-lint)
npm run lint:js    # только ESLint — его и гоняет CI
npm run lint:pug   # компиляция всех .pug и pug-lint
npm run format     # Prettier по controllers/ lib/ routes/ app.js
```

**Тестового раннера нет.** `test/index.js` — не тест, а ручной скрипт: он отправляет настоящее письмо через почтовый сервис. Проверка делается в живой админке.

ESLint смотрит только `controllers/`, `lib/`, `routes/`, `app.js`. Клиентский код в `public/` (`.eslintignore`) линтером не проверяется — синтаксис после правки проверять `node --check`.

## Окружение

Node.js 18: рабочий сервер на старой Ubuntu (GLIBC 2.24), Node 19+ там не запустится. Локально работает и более новый Node.

Настройки — в `.env` (шаблон `.env.example`), читает их `lib/config.js`. **Локальный `.env` указывает на рабочую базу** (`db.windowscalculator.net`), и `NODE_ENV=production`. Локальная админка — это рабочие данные: при проверке только открывать страницы, ничего не сохранять, не удалять, не отправлять (заказы в 1С, Homefash, письма).

Вход в админку — настоящий аккаунт. Входит человек сам; учётные данные не вводить.

## Архитектура

Express 4, Sequelize 3 поверх PostgreSQL, серверный рендеринг Pug 3. Процессом на сервере управляет PM2.

```
app.js            — middleware, сессии, статика, i18n, подключение routes
routes/           — маршруты; доступ проверяют middleware из lib/services/authentication.js
controllers/      — обработчики, по папке на раздел (orders, base, analitics, shields…)
lib/models/       — модели Sequelize; связи — lib/relationships/
lib/services/     — общая логика: PDFKit (КП), mailer, exportOrder, homefash…
views/            — шаблоны Pug
public/           — клиентский код и стили, раздаются по /assets (jQuery, d3)
update/           — старая PHP-админка, в работе не участвует
```

Уровни доступа — `LEVELS` в `authentication.js` (`USER`, `FACTORY`, `ADMIN`, `SUPERUSER`…). `isAdminAuth` пускает пользователя, завод и администратора. Часть маршрутов без проверки входа намеренно: КП и `/orders/getScheme/:id` открываются по ссылке.

**Локаль.** `lib/i18n.js`, словари в `lib/locales/` (ua, ru, en, de, it, es). Локаль привязана к запросу, но КП (`PDFKit`) ставит её на общий синглтон `i18n`: модульные помощники PDFKit не видят `req`. Не переносить это решение в другие места.

**Интеграция Homefash** — `lib/services/homefash/`, отладочная сборка выгрузки — `npm run homefash:payload`.

## КП и превью конструкций

КП заказа — `/orders/get-order-pdf/:id?userId=…&lang=…`. Без `userId` страница падает (`getOrderPDF.js` ищет пользователя с `id = NULL`); в интерфейсе ссылка всегда с параметром. HTML собирает `lib/services/PDFKit.js`: под каждую позицию ставится `<div class="schemes">`.

Превью рисует **`public/javascripts/PDF/pdf.js`** в браузере: запрашивает `/orders/getScheme/:id` (исходник конструкции и глубины профилей) и строит SVG.

Ловушка: `pdf.js` — **отдельная, давно отделившаяся копия геометрии калькулятора** (`SVGServ` и директива `svg-template` из `ekipazh-calc-frontend`). Правки геометрии и отрисовки в калькуляторе сюда сами не попадают. Новый вид конструкции в калькуляторе почти всегда требует переноса и сюда: см. `docs/features/kp-preview-shapes/`.

Проверка правки `pdf.js` — сравнение с рабочей админкой: страница КП открывается без входа, свёртка путей, заливок и подписей размеров каждой схемы у старого и нового кода должна совпасть для обычных конструкций.

## CI и выкладка

Пуш в `main` → GitHub Actions (`.github/workflows/main.yml`): `npm run lint:js`, затем выкладка по FTP и перезапуск PM2 по SSH. **Пуш в `main` — это сразу рабочий сервер.**

Что не уходит на сервер — `.ftpignore`. FTP-выкладка не удаляет с сервера файлы, которые однажды туда попали: убранный из выкладки файл остаётся там, пока его не удалят руками.

## Работа с git

- **Не коммить непроверенное.** Пока правка не проверена в живой админке, коммита не существует; чистый линтер проверкой не считается.
- **Не коммить самостоятельно.** Предлагай коммит текстом и жди решения.
- Работа — в отдельной ветке от `main`, в `main` — слиянием `--no-ff`.
- Conventional Commits, **сообщение на английском**: `fix(pdf): draw arcs as circular arcs`.
- **Не добавлять `Co-Authored-By`.**

## Документация задач

Каждая задача сопровождается документом в `docs/`. Документ ведёт Claude — программист не пишет его руками. Порядок тот же, что в калькуляторе.

**Граница с этим файлом.** В CLAUDE.md — только правила поведения и структура проекта. Всё, что относится к конкретной задаче, живёт в её документе: ход работы, замеры, обсуждавшиеся варианты, статусы, «сейчас сделано вот столько». Признак протечки — слова вроде «пока», «сейчас», «на текущем этапе».

**Расположение:** `docs/features/<ветка>/<номер>-<краткое-имя>.md`. Папка — по имени ветки без префикса, нумерация своя внутри ветки. Тип из Conventional Commits записывается полем в шапке. Индекс веток — `docs/features/README.md`, его дополнять при заведении новой ветки.

**Когда создавать:** как только пришла задача — до начала работы, дальше дополнять по ходу.

**Что внутри:** заголовок, тип, статус и связный рассказ: что нужно сделать; что обсуждалось и какие были варианты; почему выбран такой подход; что сделано; какие были проблемы и как их решили. Цель — чтобы человек через полгода понял не только результат, но и почему так.

**Статус в шапке** — только `в работе` либо `влито в main (<коммит>)`. Всё, что осталось выяснить, — в разделе «что стоит уточнить».

Если работа идёт в обоих проектах (калькулятор и админка), документ заводится в каждом, и они ссылаются друг на друга.

## Стиль

- Комментарии и документация — по-русски, в тон существующему коду. Исключение — сообщения коммитов, они на английском.
- Prettier: одинарные кавычки, точка с запятой, 2 пробела, `trailingComma: all`.
- **Окончания строк — CRLF** во всех файлах кода. Правя файл скриптом, сохранять CRLF.
- Клиентский код в `public/` — ES5 с вкраплениями ES6, без сборщика: что написано, то и уходит в браузер.
